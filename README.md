# 베이스라인 재현 결과 (자원최적화 · 전력사용량예측)

`pip install -r requirements.txt` 후 `python baseline_rf.py`, `python baseline_rnn.py`,
`python lp_optimization.py`, `python data_quality_metrics.py` 순서로 실행하면 됩니다.
결과 파일(txt/csv/png)은 전부 실행 위치 기준 `results/` 폴더 안에 자동으로 저장됩니다
(폴더가 없으면 스크립트가 알아서 만듭니다).

## 1. 랜덤포레스트 회귀 (baseline_rf.py)

가이드북 파이프라인(단계1~4: 데이터로드→개수확인→전처리→RF학습)을 그대로 따랐습니다.
타겟은 `평균`(시간당 평균 소비량), 피처는 15/30/45/60분 서브컬럼을 제외한 12개
(생산량·기온·풍속·습도·강수량·전기요금·day/d/m·공장인원·인건비·시간) — 서브컬럼은
평균과 상관계수 0.99+로 사실상 타겟의 구성요소라 데이터 누수를 막기 위해 뺐습니다.
분할은 RNN과 동일하게 9/1~9/14(336시간)를 테스트로 고정했습니다.

| 구분 | 이번 재현 결과 (시간 이상치 보정 후) | 가이드북 참고값 |
|---|---|---|
| train MSE | 23.25 | 185.98 |
| test MSE | **130.82** | 183.06 |

**정확히 일치하지 않는 이유**: 가이드북은 정확한 피처 목록·분할 방식·랜덤시드를
코드로 전부 공개하지 않았습니다(부록에 전처리 코드 일부만 공개). 그래서 100%
동일 재현은 불가능하고, 대신 "같은 자릿수(백 단위 MSE)"로 방법론이 타당함을
확인하는 것이 목표였습니다.

**"시간" 이상치 48건 보정**: 전처리 단계에서 "시간" 컬럼이 0~23 범위를 벗어난
48개 행(2021-07-13, 07-15 두 날짜)을 발견해 보정했습니다. 두 날짜 모두 24행이
그대로 존재하고 앞뒤 날짜와 행 순서(인덱스)가 이어져 있어 데이터가 밀리거나
빠진 게 아니라 "시간" 값 자체만 깨진 것으로 판단했고, 두 날짜 모두 생산량이
24시간 내내 0이라 순서를 다툴 여지가 없어 각 날짜 안에서 행이 등장한 순서를
그대로 0~23시로 재구성했습니다(행 삭제 없음 — RNN의 168시간 lag 구간에 결측
구간이 생기지 않도록 하기 위함). 보정 전 test MSE는 118.95였고, 보정 후
130.82로 소폭 변화했습니다(전체 학습데이터의 0.8%만 영향을 받아 변화 폭은
작음). 보정 후 값이 가이드북 참고값(183.06)에 오히려 더 가까워졌지만, 이는
우연의 일치이지 정확한 재현이 됐다는 의미는 아닙니다.

## 2. Simple RNN 피크전력 예측 (baseline_rnn.py)

가이드북과 동일하게 `15분` 컬럼에 대해 t-1~t-168(1주일치) lag 피처를 만들고
MinMax 정규화 후 SimpleRNN(64)→Dense(32)→Dense(1) 구조로 학습했습니다.
테스트 구간(9/1~9/14, 336시간)에서:

- test MSE: 263.39
- test RMSE: 16.23

`rnn_forecast_plot.png`를 보면 주간 가동/야간·주말 비가동의 뚜렷한 주기 패턴을
모델이 잘 따라가는 것을 확인할 수 있습니다(가이드북의 시각화와 동일한 패턴).
가이드북은 RNN에 대한 정확한 수치 벤치마크를 공개하지 않아, RMSE 16.23을
이후 XGBoost/LightGBM 비교용 자체 기준점으로 삼으면 됩니다.

## 3. 선형계획(LP) 기반 인력배치 최적화 (lp_optimization.py)

가이드북이 공개한 목적함수/제약조건은 다음과 같습니다.

- 목적함수: `Cost = P_human + P_electric` (최소화)
- 제약조건: `1≤P_electric≤2`, `1≤P_human≤75`, `11≤2·P_electric+P_human≤95`
- 가이드북 예시 출력: "생산량이 0.1718...일 때 공장직원 5.0명 투입", 최종값 610.4238

**주의**: 가이드북은 "생산량"이 이 LP에 정확히 어떻게 연결되는지(목적함수 계수인지
제약조건 우변인지)를 코드로 공개하지 않았습니다. 그래서 두 단계로 나눠 정직하게
재현/확장했습니다.

- **Part A (문자 그대로 재현)**: 공개된 3개 부등식만으로 1회 풀면 `P_electric=2.0,
  P_human=7.0, Cost=9.0`이 나옵니다. 가이드북 예시(5.0명, 610.42)와는 다른데,
  이는 생산량 연결고리가 공개되지 않아 생기는 차이입니다.
- **Part B (우리의 확장, 참고용)**: 목적함수 계수를 실제 데이터의 시간당
  `인건비`/`전기요금(계절)`로 바꿔 전체 6,168시간에 대해 LP를 반복 실행했습니다.
  전기요금 계수(약 110~190)가 인건비 계수(약 1.0~1.5)보다 훨씬 커서, 모든
  시간대에서 `P_electric=1.0`(하한), `P_human=9.0`(제약을 만족하는 최소값)으로
  수렴합니다 — 전체 시간 합산 최소비용 총계는 1,076,826.90 (`lp_optimization_result.csv`
  에 시간별 상세 결과 저장).

## 4. 데이터 품질 6대 지표 (data_quality_metrics.py)

가이드북 부록 4장의 산식(완전성/유일성/유효성/일관성/정확성/무결성)을 실제
데이터에 그대로 적용했습니다.

| 지표 | 가이드북 참고값 | 보정 전 | 보정 후 |
|---|---|---|---|
| 완전성 | 99.68~100% | 99.98% | 99.98% |
| 유일성 | 99.69% | 100.00% | 100.00% |
| 유효성 | 100.00% | 99.22% | **100.00%** |
| 일관성 | 100.00% | 100.00% | 100.00% |
| 정확성 | 측정 제외(컬럼 독립) | 측정 제외 | 측정 제외(가이드북과 동일) |
| 무결성 | (합산공식 비공개) | 99.80% | **100.00%** (측정 가능한 4개 지표 단순평균, 우리 정의) |

**유효성이 보정 전 99.22%였던 이유**: 유효성 검사에서 "시간" 컬럼이 0~23 범위를
벗어난 행 48개(2021-07-13, 07-15)가 걸러졌기 때문입니다. 위 "1. 랜덤포레스트
회귀" 섹션에 설명한 보정 로직(행 삭제 없이 날짜별 순서로 0~23시 재구성)을
`data_quality_metrics.py`에도 동일하게 적용해, 보정 후 유효성·무결성 모두
100.00%로 개선된 것을 확인했습니다. 가이드북이 사용한 데이터 버전에서는 이
이상치가 이미 없었거나, 유효성 검사 범위에 "시간" 컬럼을 포함하지 않았을
가능성이 있습니다. 무결성은 가이드북이 정확한 합산 공식을 공개하지 않아
측정 가능한 4개 지표의 단순평균으로 근사했습니다(가이드북의 공식이 아니라
우리가 정한 방식임을 명시).
